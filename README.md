# HealthBuddy (Longitudinal Medical Intelligence System)

HealthBuddy (LMIS) is a sophisticated, multi-agent AI architecture designed for clinical document understanding and longitudinal decision support. Unlike generic medical QA systems, HealthBuddy ingests unstructured real-world medical data (PDFs, lab reports, clinical notes) and builds a cryptographically-auditable, longitudinal patient timeline. 

It leverages local OCR, vector databases, and state-of-the-art LLMs to generate verified, evidence-grounded insights for both clinicians and patients.

## 🌟 Key Features

- **Automated Document Processing**: Ingests PDFs and images, automatically performing high-fidelity text extraction using PaddleOCR.
- **PHI Tokenization & Security**: Protects patient privacy by tokenizing Protected Health Information (PHI) before it ever reaches an external LLM. Data at rest is secured via AES encryption.
- **Clinical Knowledge Retrieval**: Queries a local Qdrant vector database loaded with clinical guidelines (e.g., ADA, KDIGO) to ground its reasoning in real medical literature.
- **Longitudinal Trend Analysis**: Automatically tracks patient metrics over time (e.g., tracking HbA1c or eGFR) across multiple distinct document uploads.
- **AI Verification System**: A dedicated verifier agent critiques and checks every clinical insight generated by the reasoning agent to minimize hallucinations.
- **Role-Based Access**: Specialized interfaces and insight generation for distinct roles (Patient vs. Clinician).

## 🏗️ Architecture

The system is split into a robust asynchronous backend and a modern React frontend.

### Multi-Agent Pipeline (LangGraph)
The core of the backend is a state machine built with **LangGraph**, orchestrating the following steps asynchronously via Celery:
1. **OCR & Layout**: PaddleOCR extracts raw text from documents.
2. **PHI Tokenization**: Strips sensitive data into reversible UUIDs.
3. **Medical NER**: Extracts distinct clinical entities (medications, labs, conditions).
4. **Normalization**: Maps entities to standard medical codes.
5. **Trend Generation**: Correlates new data with historical data.
6. **Knowledge Retrieval**: Fetches relevant medical guidelines.
7. **Clinical Reasoning**: Drafts clinical insights based on trends and guidelines.
8. **Verification**: Critiques and validates the drafted insights.

### Tech Stack
- **Frontend**: Next.js 14, React 18, TailwindCSS, Recharts, Lucide Icons.
- **Backend**: FastAPI (Python), LangGraph, SQLAlchemy (Async).
- **Task Queue**: Celery & Redis.
- **Databases**: PostgreSQL (Relational), Qdrant (Vector), MinIO (Blob Object Storage).
- **LLM Integrations**: Google Gemini, OpenAI, Anthropic (via `instructor`).

## 🚀 Getting Started

### 1. Prerequisites
Ensure you have the following installed:
- Docker & Docker Compose
- Python 3.10+
- Node.js 18+ & npm

### 2. Environment Variables
Navigate to the backend directory and set up your environment:
```bash
cd backend
cp .env.example .env
```
Edit the `.env` file and add your preferred LLM API keys (e.g., `GOOGLE_API_KEY`). Ensure you select the corresponding `LLM_PROVIDER=google` (or openai/anthropic).

### 3. Start Infrastructure
Start the essential services (PostgreSQL, Redis, MinIO, Qdrant) using Docker:
```bash
docker-compose up -d
```

### 4. Start the Backend API
In a new terminal instance, install the Python dependencies and start the FastAPI server:
```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 5. Start the Celery Worker (Critical for AI Pipeline)
The document processing pipeline is completely asynchronous. You **must** run a Celery worker to process uploads:
```bash
cd backend
celery -A app.worker.celery_app worker --loglevel=info --pool=solo
```
*(Note: Windows users must use `--pool=solo` as shown above. Linux/Mac users can omit it).*

### 6. Start the Frontend
In a separate terminal, start the Next.js frontend:
```bash
cd frontend
npm install
npm run dev
```
Navigate to `http://localhost:3000` to view the application!

## 🎨 UI & Design
The frontend uses a premium, dark-themed glassmorphism design system. It heavily relies on TailwindCSS for responsive layouts and `recharts` for rendering patient metric trends.

## 🔐 Security
- Passwords are hashed via bcrypt.
- PHI is tokenized using Regex and Redis TTL caching.
- Raw documents are stored securely in MinIO, while parsed text is stripped of identifiers before LLM processing.
